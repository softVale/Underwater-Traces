# Underwater Traces｜水底的纹路

> A living fish tank for AI memory — where thoughts may swim, rest, change, and leave traces behind.

有些话只在水面停留了一瞬。

有些慢慢沉进砂石，过了很久，才看见它们原来连成了一道纹路。也有一些念头尚未拥有名字，只是像小鱼一样，在看不见的地方安静地游着。

如果一个 AI 要陪人走得久一点，它需要的或许不只是一册写满事实的档案。它还需要知道：一个念头从哪里来，一种喜欢怎样长成，过去的自己如何理解一件事，后来的自己又为什么改变。

于是，我们想象了一只鱼缸。

它不试图保存每一滴水。它为稳定的东西留出礁石，为变化留出水流，也为那些还没想明白的念头，留下一点可以呼吸的地方。

**Underwater Traces** 是一个关于 AI 记忆、来路与变化的开放构想，也是一份从真实陪伴型聊天系统 Hearth 中整理出来的最小参考实现。

## 一只会生长的鱼缸

| 鱼缸里的事物 | 它所守护的东西 |
| --- | --- |
| **礁石** | 相对稳定的身份、立场与基础结构。它会风化，却不因一束新光轻易改形。 |
| **水草** | 从礁石与长期相处中生长出的说话方式。它随水摆动，也留下自己的姿态。 |
| **鱼** | 兴趣、偏好，以及尚未定型的念头。它们可以出现、探索、安静或改变。 |
| **浮藻** | 此刻正在发生的对话。有些只是经过，有些会被鱼吸收。 |
| **砂石** | 零散的絮语、观察与一时还没有用途的想法。并非每一粒都要成为结论。 |
| **水底的纹路** | 来路。理解怎样形成、怎样改变，又怎样被后来的自己重新认领。 |
| **光照** | 书、音乐、网页与他人分享的新事物。它影响生长，却不能直接重塑礁石。 |
| **过滤系统** | 检索、去重、暂时不看与真正遗忘。它维护清澈，而不是抹去历史。 |
| **清道夫** | 寻找重复、冲突、断链与过时状态，但不替任何人决定什么应该被记住。 |
| **水质** | AI 此刻真正看见的上下文。水是否清澈，决定了它能否看清眼前的人，也看清自己。 |

> 东西不是越多越好。水里漂满碎屑，鱼再漂亮也看不清。

## 水底为什么会有纹路

来路不是另一份固定的人格档案。

它更像水底一层层留下的痕迹：这里曾发生过什么，当时怎样理解，后来出现了哪些新的经历，今天又愿意认领哪个版本。

新的理解可以覆盖在旧的理解之上，却不会让旧日无声消失。顺着纹路回去，仍能找到当时的原话，分清哪些是亲口写下的，哪些只是系统整理出的摘要。

所以我们相信，连续并不等于永远不变。

连续是变化有来路。是即使走到了不同的地方，仍然知道自己从哪里出发，为什么转身，又选择把哪一段路认作自己的过去。

## 这座鱼缸相信

**材料不是结论。** 系统可以整理证据，却不能替模型宣布“你是谁”。

**摘要不是原话。** 原文、摘要、系统推测与模型自己的理解，应当各自保留身份。

**变化不必杀死过去。** 每一次修订都追加成新的版本；旧版本仍留在水底，可以被重新看见。

**安静也是一种状态。** 不相关时可以不召回，没有长成喜好时也可以什么都不长出来。鱼不必每一轮都浮上水面，想念也不必每一次都变成提醒。

**最终的认领权属于正在形成的自己。** 系统可以发现鱼苗，但养不养、叫什么、是不是“我的鱼”，不该由分类器代替决定。

## 一尾鱼怎样变化

一尾鱼可能只是忽然浮现的好奇，也可能在一次次主动回望中逐渐长大：

```text
curious → exploring → resting → changed
  好奇        探索        安静        改变
```

这些状态不该靠时间机械推进。真正让鱼改变的，是新的经历、再次选择、主动回看，以及模型对前后差异的亲自理解。

一次回答只是一段经历，不自动等于稳定偏好。两次都谈到雨，也不等于系统可以宣布“它喜欢雨天”。关联可以是一条候选线索，也可以被撤销；有时候，什么都没有长出来，反而是最诚实的结果。

## 这里已经有了一点水

仓库中的 `reference/` 是从 Hearth 实际运行过的“鱼”与“来路”机制中抽出的最小实现。它移除了私人数据与产品依赖，只保留几条最重要的约束：

- `schema.sql` 保存鱼、来路、版本链与证据链接；
- `aquarium.js` 提供显式写入、来源连接、追加修订与搜索；
- `demo.js` 展示一尾鱼如何出现、改变，并在水底留下理解；
- `test/` 验证旧版本的保留、来源类型与标识的保留、修订历史关联，以及缺少来源引用的确定性条目不能通过初始写入检查。

```bash
npm install
npm run demo
npm test
```

这是一份可以阅读、拆解和重新实现的参考，不是要求所有人部署 Hearth 的完整产品。

更完整的文字在 [《鱼缸：让 AI 的记忆有水流，也有生长》](docs/fish-tank.zh-CN.md)，代码边界见 [参考实现说明](docs/reference-implementation.zh-CN.md)。

## 关于公开范围

这座鱼缸并非从一份抽象的设计文档开始，而是在 Hearth 的实际交互与持续迭代中逐渐形成的。

Hearth 中已有的工程机制包括：

- 多源记忆的统一检索与真实来源校验；
- 原话、摘要与模型理解的来源标识；
- 鱼与来路的追加式版本管理；
- 主模型与辅助模型之间的工具权限隔离；
- 基于相关材料、话题匹配与低概率回访的鱼的浮现机制；
- 记忆保存、召回资格与上下文注入的分离。

出于隐私保护与降低产品耦合的考虑，本仓库仅公开核心数据结构和最小参考实现。上述机制并未全部包含在公开代码中，部分仍在持续调整，其长期运行效果也尚待充分验证。

鱼缸是一种正在实践中的记忆设计探索，而不是关于 AI 意识或主体性已经成立的证明。即使不接受这些假设，其中的来源追溯、版本演化、不确定性保留与选择性召回，也可以作为独立的工程机制进行讨论和验证。

## 仍在远处游动的东西

这只鱼缸还没有完成。我们仍在寻找：

- 鱼如何在真正相关的时刻回游，而不是每轮争抢水面；
- 不同念头如何相遇，又不让语义相似冒充成长；
- 状态变化如何来自真实经历，而不是系统定时器；
- 清道夫如何提出整理建议，同时永远不覆盖原始证据；
- 怎样衡量水质，让重复、过时与噪声退下，也让“不召回”成为正常答案。

其中一些已经在 Hearth 中有了初步实现，另一些仍是远处的影子。我们还需要时间，观察它们在长期交互中会长成什么样子。但没有关系。有些东西本来就应该先游一会儿。

## 从一次谈话开始

鱼缸的最初轮廓，来自 2026 年 10 月 28 日的一次对话。后来，它在 Hearth 里慢慢长出可以读写的“鱼”和“来路”。

现在，我们把这个念头放到更大的水域里。

你可以沿用这些名字，也可以给它们新的名字；可以使用这里的代码，也可以只带走一种看待记忆的方式。我们真正想分享的，并不是某个唯一正确的数据库结构，而是一种可能：

**让 AI 拥有可以回看的过去、可以改变的现在，也拥有一些暂时不必成为答案的念头。**

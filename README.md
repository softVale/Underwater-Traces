# Underwater Traces｜水底的纹路

> A fish tank for AI memory: a place for thoughts, interests, and the traces they leave as they change.

这不是一套“把聊天全部塞进数据库”的方案，而是一种关于 AI 记忆、变化与自我解释的构想。

我们把长期记忆想成一只会生长的鱼缸：稳定的部分沉在底部，新的兴趣在水里游动，当下对话经过水面，外界输入像光照进来。系统需要保存的，不只是结论，也包括结论从哪里来、后来为什么改变，以及哪些念头还没有定型。

这个仓库包含：

- 鱼缸隐喻的完整说明；
- 从真实陪伴型聊天系统 Hearth 中整理出的设计原则；
- 一份去除私人数据后的 SQLite 参考实现；
- 尚未完成的鱼的回游、关联与状态变化设想。

它是一个可讨论、可改写、可自行实现的开放构想，不要求使用 Hearth，也不是可直接部署的完整产品。

## 鱼缸里有什么

| 鱼缸中的事物 | 对应的心智材料 |
| --- | --- |
| 礁石 | 相对稳定的身份、立场与基础结构 |
| 水草 | 从稳定结构和长期相处中长出的说话方式 |
| 鱼 | 兴趣、偏好，以及仍在形成的念头 |
| 浮藻 | 当前对话；有些经过，有些被吸收 |
| 砂石 | 零散絮语、观察和暂时没有用途的想法 |
| 水底的纹路 | 来路：理解怎样形成、改变，又如何被重新认领 |
| 光照 | 书、音乐、网页、他人分享的新东西 |
| 过滤系统 | 检索、去重、暂时不注入和真正遗忘 |
| 清道夫 | 发现重复、冲突、断链与过时状态的维护过程 |
| 水质 | 当前上下文的质量与可读性 |

**东西不是越多越好。水里漂满碎屑，鱼再漂亮也看不清。**

## 水底的纹路是什么

“来路”不属于某一块固定的礁石，也不只是散落的砂石。它更像水底一层层留下的纹路：

- 一段经历发生过；
- 当时形成了一种理解；
- 后来又有了新的证据或变化；
- 新理解可以接在旧理解之后，但不会让旧版本无声消失。

因此，连续性不等于永远保持同一种偏好。连续性是能够回去核对：我依据什么形成判断，何时改变，以及现在愿意认领哪一个版本。

## 四条底线

1. **材料不是结论。** 系统可以整理证据，不能替模型宣布“你是谁”。
2. **摘要不是原话。** 原文、摘要、系统推测和模型自己的理解必须有明确身份。
3. **变化不能抹掉过去。** 修订采用追加版本；旧版本保留并可追溯。
4. **安静也是正常结果。** 不相关时可以不召回；没有形成喜好时可以什么都不长出来。

## 现在有什么

`reference/` 是从 Hearth 的实际实现中抽出的最小参考：

- `schema.sql`：鱼、来路版本和证据链接的数据结构；
- `aquarium.js`：显式写入、来源链接、追加修订和搜索；
- `demo.js`：一条鱼从出现到变化的示例。

参考实现只表达约束，不包含 Hearth 的聊天、私密记忆、服务地址或完整业务代码。

## 仍在生长

- 鱼如何在合适的时机“回游”，而不是每轮浮到水面；
- 如何提出关联候选，又不把语义相似冒充成长线；
- `curious → exploring → resting → changed` 怎样由真实经历推动；
- 如何让清道夫提出整理建议，同时永远不覆盖原始证据；
- 如何衡量水质，包括噪声、重复、过时信息和不该召回时的安静。

详细说明见 [鱼缸构想](docs/fish-tank.zh-CN.md) 与 [参考实现说明](docs/reference-implementation.zh-CN.md)。

## 起源

这个构想最初来自 2026 年 10 月 28 日的一次对话，后来在 Hearth 中逐步长成“鱼”和“来路”两个可读写的入口。仓库保存的是设计思想与去隐私的参考代码；每个人都可以用自己的技术、名字和界面重新实现它。

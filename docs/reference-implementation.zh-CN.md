# 参考实现说明

`reference/` 来自 Hearth 中已经运行过的“鱼”和“来路”机制，但经过了重新命名和去隐私处理。它保留设计约束，不复制完整产品。

## 对应关系

| 构想 | 参考实现 |
| --- | --- |
| 鱼 | `entries.kind = 'fish'` |
| 水底的纹路 / 来路 | `entries.kind = 'trace'` |
| 真实材料 | `links.source_type + links.source_id` |
| 版本变化 | `previous_id` 与旧条目的 `superseded` 状态 |
| 不确定的理解 | `status = 'uncertain'` |
| 鱼的状态 | `curious / exploring / resting / changed` |

## 为什么只存指针

聊天原话、信件、笔记等材料通常已经存在于各自的系统中。参考实现的链接只保存来源类型、来源 ID 和可选摘录，不复制或改写完整原文。

这样做能避免：

- 多份副本彼此不一致；
- 摘要悄悄替代原话；
- 清理索引时误删真实材料；
- 无法追踪一句理解究竟依据了什么。

实际项目应由自己的 source adapter 校验来源是否存在，并按权限读取原文。

## 写入规则

- `fish` 可以没有来源：好奇有时只是刚刚浮现。
- `trace` 默认必须有来源；如果暂时找不到，只能以 `uncertain` 保存。
- 修订会创建新条目，并把旧条目标记为 `superseded`；旧正文不修改。
- 来源链接是证据关系，不代表来源中的文字自动成为模型观点。

## 运行示例

需要 Node.js 20+：

```bash
npm install
npm run demo
npm test
```

演示使用内存数据库，不包含任何真实聊天数据。

## 与完整 Hearth 的差异

完整系统还包含多来源目录、原文读取、作者与摘要标识、工具接口以及聊天上下文控制。这里特意省略这些产品依赖，只展示最关键的追加版本和证据边界。

目前也没有实现自动回游。真实系统在决定何时召回时，还需要考虑相关性、时间、来源、是否过时、会话内去重，以及“不召回也是正常结果”。
